# DSH-Chat 使用与管理

将插件放到 `Yunzai/plugins/dsh-chat`，安装依赖后重启 Yunzai。运行环境、固定 DSH fork 的构建和部署见项目 README。插件不接管 QQ 登录；消息经 NapCat → Yunzai 进入。

## 开始聊天

- 私聊发送普通文字。
- 在已启用的群内 `@机器人 你好`。
- 使用配置前缀，默认 `#聊 你好`。

默认群白名单为空，群消息不会触发聊天。主人需在 Guoba 中填写 `permissions.groupWhitelist`；群内所有人共享该群的会话，私聊按 QQ 独立保存。

同一个会话串行处理，不同会话受全局并发限制。繁忙时会排队；`#dsh 取消` 取消当前会话正在进行的回复。重启后按 ACP 能力恢复原 session，恢复失败时创建新 session。

## 命令

`#dsh` 和其后的子命令之间使用空格。命令是否需要主人身份由运行时统一检查，不依赖消息正文中的身份声明。

| 命令 | 用途 |
|---|---|
| `#dsh 帮助` | 查看当前版本支持的命令 |
| `#dsh 状态` | 查看连接、队列和当前会话状态 |
| `#dsh 面板` | 查看 Guoba 配置入口 |
| `#dsh 模型列表` | 从当前 ACP 会话读取实际模型选项 |
| `#dsh 模型 provider/model` | 为当前聊天切换模型；从下一轮生效 |
| `#dsh 推理 选项值` | 设置当前模型支持的推理强度 |
| `#dsh 清空` | 清空当前聊天的 session 映射，后续建立新会话 |
| `#dsh 取消` | 取消当前聊天的正在运行任务 |
| `#dsh 记忆 关键词` | 检索有权限访问的记忆 |
| `#dsh 记住 内容` | 手动记录当前作用域的记忆 |
| `#dsh 遗忘 ID` | 将指定记忆标记为过时 |
| `#dsh 恢复 ID` | 恢复被遗忘的记忆 |
| `#好` / `#不好 说明` | 对当前聊天中的最近回复记录反馈 |
| `#dsh 人格 候选 新人格文本` | 保存待审批的人格候选 |
| `#dsh 人格 列表` | 主人查看人格版本与候选 |
| `#dsh 人格 审批 ID` | 主人批准指定人格候选 |
| `#dsh 人格 回滚 ID` | 主人恢复指定人格版本 |
| `#dsh 人格 暂停` / `#dsh 人格 继续` | 暂停或继续反馈学习 |
| `#dsh 写信 标题\|正文` | 保存文本信件 |
| `#dsh 发信 ID` | 发送已保存的信件 |
| `#dsh 重启` | 主人重启 ACP 连接 |
| `#dsh 反思` | 汇总最近反馈；开启模型反思后生成待审批人格候选 |
| `#dsh 日志` | 主人查看最近日志摘要 |

模型切换、会话清理、全局配置、遗忘/恢复和人格审批等管理操作需要主人。普通成员可在已允许的聊天中交流、提供反馈，并在功能开启后操作本人/本群的记忆；不能访问其他人的私聊。运行时帮助会标明更细的命令限制。

`清空` 不删除 DSH 的历史存储，也不会删除记忆。人格审批和回滚不修改插件代码、密钥和权限。

## Guoba 配置

安装兼容 Yunzai V3 的 Guoba-Plugin，在其插件配置中选择 **DSH-Chat**。插件通过根目录 `guoba.support.js` 导出标准 `supportGuoba()`，不另外启动 Web 服务。

建议按以下顺序配置：

1. 连接：填写 fork 构建的绝对路径、完整 commit、独立 `DSH_HOME` 和 `qq` profile。
2. 权限：确认主人 QQ，填写群白名单。
3. 模型：先查看 `#dsh 模型列表`，再填写实际存在的 provider/model。默认关闭免费模型。
4. 按需要启用图片、记忆、表情、语音、文件、写信等工具。
5. 开启日志正文前确认聊天内容适合保存在本地日志中。

配置保存会经过校验；正在处理任务时，涉及运行中资源的更改可能被拒绝，待任务结束后再保存。连接配置和人格的生效方式见 README。

Guoba 提供基础配置表单。会话状态、模型实时列表、记忆检索、反馈、人格审批和日志查询通过上述命令完成；本版未提供表情预览墙等自定义组件。

`memory.autoExtract` 和 `learning.autoReflect` 默认关闭。前者在聊天完成后额外调用模型提取少量长期记忆；后者在反思任务执行时额外调用模型生成待审批的人格候选。两者共用 `memory.extractionModel`，留空使用默认账号模型，拒绝免费模型。这些调用消耗额外模型额度，分别受每日自动记忆和候选数量限制；候选不会自动替换当前人格。

## QQ 能力与降级

- 图片和文件先经过媒体服务转存与校验；发送适配器只读取插件媒体目录中的普通文件。
- 文件仍要求主人或群管身份。开启功能不会提升成员权限。
- 语音优先使用适配器实际提供的 QQ TTS；没有可用的语音能力时发送文本。
- QQ 空间默认关闭。仅在注入的适配器实际提供 `bot.qzone.post/comment/like` 时支持对应操作；标准 NapCat 缺少接口时返回明确的能力不可用错误。
- 表情包收录仅识别真实表情标记，不将普通聊天图片全部收录。
- 群聊仅挂插件受控 MCP 工具。本版不开放模型读取任意本地文件、执行终端命令或自动修改权限的能力。

## 排查

| 现象 | 检查 |
|---|---|
| 群内没有回复 | 总开关、聊天开关、群白名单、@ 或前缀触发 |
| 私聊没有回复 | 私聊开关、Yunzai 事件来源、DSH 连接配置 |
| 连接被拒绝 | 构建路径、commit、独立 `DSH_HOME` 和 profile 是否按部署说明配置 |
| 模型不在列表 | 当前 `qq` profile 是否挂载相应 provider；不要手填未注册模型 |
| 免费模型被拒绝 | 免费模型开关、上游限额、地区可用性和模型实际能力 |
| QQ 空间不可用 | 适配器是否真正实现对应空间接口 |
| 媒体被拒绝 | 大小、格式、来源和最终路径是否通过媒体服务校验 |

报错时先查看 `#dsh 状态` 和主人可见的日志摘要。不要把模型凭据、登录态、完整聊天记录或未脱敏的日志发到公共群。
